# Learning Blocks - Development Guide

For what the mod is and how it plays, see [README.md](README.md).

## Installation

Install server-side alongside its declared dependencies (see `fabric.mod.json`); connecting clients need only Pandorical. Version targets live in `gradle.properties` (Minecraft, loader, Fabric API) and `fabric.mod.json` (Java).

## Building

`./gradlew build` leaves the jar in `build/libs`. Pandorical is a subproject pointed at `../pandorical`, so a change there is compiled straight into this build with nothing published in between. Java is compiled with `-Werror`.

The source is split three ways: `src/main` is the mod, `src/gametest` the tests, and `src/client` is empty on purpose. Pandorical draws everything on the client, so there is no client code to ship; the source set is there so the split already exists the day something genuinely client-only turns up.

## Testing

```
ALSOFT_DRIVERS=null xvfb-run -a ./gradlew --no-daemon runClientGameTest -Ptest.level=full
```

Launches a client off-screen and silent (`ALSOFT_DRIVERS=null` gives OpenAL its null device, "OpenAL initialized on device No Output" in the log, and `--no-daemon` makes sure the variable reaches the game), joins a world and runs every test listed in `src/gametest/resources/fabric.mod.json`, in that order. `-Ptest.level=full` runs everything, screenshots included; without it, a smoke run skips the screenshots and the slowest parts.

The test mod's `TestDefaults` starts new readers on words, and `TestClientDefaults` sets the render distance to 4: every tick is drawn in software, and nothing tested is further away. Each test's class javadoc says what it checks; the table is a map.

## Assets

The letter tiles are drawn by `generate_textures.py` and modelled by `generate_models.py`; both are pure standard-library Python and deterministic. Change a script and run it rather than editing its output. There is one `letter` block with a `letter` state (every `Letter`: the letters, two- and three-letter tiles, capitals, and `blank` for the gap) and a `lit` state, gold, for the tile whose sound is being said; its item carries the letter in its `block_state` component, which `items/letter.json` selects the model by.

## Sounds

Every sound goes through `sound/Sounds.java`, named by its kind, a folder under `sounds/`: `phoneme/<x>`, `word/<w>`, `phrase/<p>`, `blend/<word>/<i>`, `name/<letter>`, `number/<n>`, `scene/<s>` and `sfx/<s>`. The recordings are made by `generate_sounds.py` (ElevenLabs, cached in `.sound-cache/`, so re-running is free unless a line changed) into `src/main/resources/assets/learning-blocks-justfatlard/sounds/<key>.ogg`. Don't edit its output by hand; change the script and run it.

At start-up `Sounds` finds every `.ogg` there, writes a `sounds.json` naming each one, and hands it to Pandorical with the files. Ship a `sounds.json` of your own instead and it is kept, and whatever it names counts as recorded. Recordings are played as `Holder.direct(SoundEvent.createVariableRangeEvent(id))` and never registered in `BuiltInRegistries.SOUND_EVENT`, so they travel only through Pandorical's asset sync. A key with no recording plays a note-block placeholder (consonants on the harp, vowels on the bell, each letter its own pitch).

Two ways to play: `play(player, key)` is the room's voice, to that child only, as if beside them; `playAt(level, pos, key)` comes from a block, heard by everyone near it and from where it is. `Sounds.recent()` keeps the last few played, which is what the tests listen through.

Sound keys: `phoneme/<v>` is a vowel's short sound, `phoneme/<v>_long` its long one (the letter's name). A loose tile says its default (`LetterBlock.phoneme(state)`, by grapheme, so the sh tile says /sh/); a letter in the word row says what the word says (`Word.soundOf(i)`): nothing if the word file's `sounds` says `silent`; else `blend/<word>/<i>` if that recording exists (a vowel cut from the word's own recording, which wins over an override such as `a_long`); else `phoneme/<sounds[i]>`; else `phoneme/<tile>`. `Word.phonemeOf(i)` is the same without the cut clip. The row is the word the gap spells, so a wrong "bat" blends with `blend/bat/1`. Loose tiles and the review screens always use `phoneme/<x>`. A tile speaks when placed by anyone anywhere, broken, blown up, right-clicked with an empty hand, or punched. Punches are heard through `PunchMixin` on the left-click punch packet: a breakable tile speaks once on the click that starts a break (and the break stays quiet if the click spoke within 12 ticks), a board letter repeats every 6 ticks while held. The block is built on white wool, both server-side and as Pandorical's client stand-in, so its own place, break and step sounds are a soft thud under the voice rather than a wooden clunk over it.

## Captions and narration

Each clip has a caption file, `data/learning-blocks-justfatlard/learning_captions/<kind>/<name>.json`, written by `generate_sounds.py` from the same timestamps it cuts the audio by: the clip's `duration`, and each spoken word's `start` and `end` in seconds. `sound/Captions.java` loads them as server data, because the server runs the timeline. A clip without one plays with no caption and a length guessed by kind.

`narration/Narration.java` is a list of steps, each a clip, an in-world action, or both; `narration/Narrator.java` plays one per player on the server tick, a step lasting its clip's duration plus a gap. Starting a narration stops the one before; leaving and logging out stop it too, and stopping runs the narration's `onStop`. What happened is kept in a short per-player log (`light:0`, `clip:phoneme/c`, `outcome`), which the tests read.

`narration/CaptionHud.java` draws the caption as a Pandorical HUD overlay, one text component per word at the player's size (2, 2.5 or 3), each word gold while it is said, white once said, grey before. Pandorical places components rather than flowing them, so words are measured on the server with `FontWidths`, the vanilla default font's advances, measured from `font/ascii.png`. `narration/CaptionLayout.java` fits the words to the player's window, which Pandorical reports as `screens().viewport(player)` in scaled GUI pixels (320 wide until the client reports): greedy wrapping onto at most three lines, each within the window less margins; only if three lines can't hold it is the scale brought down in steps. From the top, extra lines grow down; from below, up. A line comes down shortly after it ends unless another replaces it.

The room's narrations, built by `puzzle/RoundLifecycle.java` (the prompt) and `puzzle/AnswerNarration.java` (the button):

- **Prompt**, on each round and again after 20 quiet seconds (twice a round at most): "Can you make..." then the word.
- **Blend**, on the button: "Let's sound it out!" the first time, then each tile's phoneme with its board tile lit and the caption building `c · a · t`, then the word with every tile lit and the caption snapped to `cat`.
- **Right**: counted at the press (`AnswerCommit`), then the word happens, then the word again, "You did it!", "Here comes another one!", and the next round.
- **Wrong** (a real word, just not the one asked for): the miss counted at the press, then "Oops! That's..." and the word, then its `wrong` outcome happens (the ordinary one if it has none), then the prompt again.

Nothing the room says goes to chat or the action bar. The held-item name and action-bar message are hidden inside the classroom (Pandorical `hideVanillaElements`), since both sit where the caption does.

## Prizes

`reward/PrizeConfig.java` reads `config/learning-blocks/prizes.json` leniently (JSON with comments), writing the commented defaults first if there is none; it is read at server start, after the registries exist, and by `/learn reload`. Bad entries are collected as problems and skipped. `reward/Prize.java` is the kinds of prize (items, experience, loot, a plushie, a toy, a toybox pick), each checked against the server's registries as it is read. `reward/Prizes.java` is told of every enter, solve and miss by the room and decides what pays; `reward/Progress.java` is the persistent, copied-on-death attachment holding what a child has read and what has paid. A payout is resolved at once (a loot table is rolled then) into stacks and experience in the `Visit`, never the classroom inventory. `Travel.goHome` gives the stash back, teleports, then `settle` hands the prizes over and ends the visit, all in one tick; every backstop ends in the same `settle`.

## Survival, and what it allows

The classroom is survival so tiles break and place the ordinary way; `Rooms.useBlock`, `Rooms.mayBreak` (on `PlayerBlockBreakEvents.BEFORE`) and `Rooms.useItem` hold everything else back for anyone not in creative. Only a `letter` block breaks, and only loose on the floor or in the gap; a tile places only in the gap or on the room's floor; no other item is used on a block; buckets and spawn eggs do nothing. The board's own letters, and the underscore painted at the back of the gap, are a separate `board_letter` block, unbreakable, whose Pandorical stand-in stands on bedrock so the client never starts digging it. The tile block has hardness 0.2 (six ticks by hand) on both sides, and a loot table that drops the tile with its letter. `Interaction.keepSolvable` puts back the target's tile every two seconds if it is nowhere.

Everything a word does comes out of the button, `puzzle/Dispenser.java`: `dispenseCreature`, `dispenseItem`, `dispenseWorn`, `dispenseBlock` (the spot is chosen and reserved as it leaves, the block placed and tracked when it lands), `dispenseEffect` (an end-rod trail, the effect on arrival), `dispenseFirework`, `strike`; a sequence's parts leave `Dispenser.STAGGER` ticks apart. Outcomes and scenes see only the `RoomEffects` interface, not the room. `Room.later` only runs while the room and the round are still the same. `Room.dispensed()` records where each thing started, for tests.

Tiles are placed by the room itself (`Rooms.useBlock`, then `Interaction`): aimed at the gap - the gap, the tile in it, the underscore, the board around the underscore - `putInGap` swaps; anywhere else in the room, `sendHome` flies the tile back to its own floor spot. After a wrong word `returnGapTile` does the same. `keepSolvable` puts every shelf tile back if it is nowhere. A new stage (or `/learn stage`) runs `resetForStage` and says `phrase/next_level` before the prompt; the last word of a stage drops "another one" for it. Lessons: `Visit.lessons` counts down on each solved round; while any are left (and the child is not an operator) the portal is dark and walled with the count over it, the portal and `/learn leave` refuse, `more_to_go_<n>` (`Travel.moreToGo`, up to `MOST_LESSONS`) follows a solve and `Portal.openLine` the last; lessons left when something else takes the child out move to `Progress.lessonsOwed`, and the next login sends them back in. The prize chest's line plays once, via `Narration.sayIf` and `PrizeShowcase.takePrizeNews`, and opening the chest is a view-only Pandorical screen (`PrizeChestScreen`). The picture's click box is an `Interaction` entity; `Room.replay` repeats the prompt at most every 30 ticks.

The first prompt of a visit is held until the client says it has loaded the level (`PlayerLoadedMixin`, on the loaded packet a client sends after every dimension change) and a second more, or eight seconds at most, and dropped if the child is already busy by then. The picture over the board is an item display, `Word.picture()`.

## Stages and outcomes

`puzzle/Stages.java` is where a child is: the first band (see Bands) at or past their floor with an unmastered usable word, and its stage, or -1 once all are done. `Progress.words` is what they've read, for stages and My words; `Progress.rewarded` is what has paid "new word" and is never taken out of, so `/learn stage` can make a child read words again without paying twice. `Puzzle.pick` takes the stage and what's read and prefers families with something unread.

`puzzle/Outcome.java` is a sealed interface dispatched on `type`, one record per kind, each with its own codec, `usable()` check and `run(player, room)`. Anything a word does to the room goes through the `RoomEffects` it is given (the room's `Dispenser`): `place` (free floor only, tracked, cleared by `clearRound` and `close`), `scale` (a transient modifier, removed on time and in `close`), `creatures`, `keep`. Taming uses `setTame` and `setOwner`, not `tame`, which awards an advancement. `Word.wrongOutcome()` is `wrong` if usable, else `outcome`. Wrong outcomes' short-lived things go through the same: `act` (spin, bounce, sneeze, bonk, circle, flee, `lasts`), `vanishBlock`, `throwSnowball`, `bonk`, `spin` (per-tick relative teleports of the yaw), `roll` (an item display), and `props`, cleared with the creatures on a new stage and in `close`. `scale` remembers its end time, so an earlier size's timer never cuts a later one short.

## The letters level

Stage 0 (`puzzle/Letters.java`): groups, keywords, sound-alike tiles (`SAME_SOUND`: c, k, ck and q never together as distractors), knowing (`Progress.letterHits` against `letter_known_after`), targets and distractors. `Stages.current` is 0 while `stage_floor` is 0 and a letter is unknown; a fresh `Progress` has floor 0 when `letters_first` is on (`Progress.lettersFirstForTests` overrides it: the test mod's `TestDefaults` starts every test on words, and `LettersLevel` turns letters on). A letters round is an ordinary `Puzzle` whose target is the letter as a one-tile `Word`, so the row, tiles and fly-home rules are a word round's; `Room.prompt` asks `which_letter_says`/`find_the_letter` (taking turns) and the sound, with a "♪" caption, and `Room.pressLetter` chants or sends the tile home. `Prizes.letterSolved` counts first-try hits and pays events as a word does (`rewarded` gets `letter:<x>`, and stage 0 complete is `stage_complete` for stage 0). Keyword-only words (`"keyword": true`) are in `Words.keywords()`, never `Words.all()`. Early blending: once the first group is known, `Letters.wordDue` makes one letters round in `letter_word_every` a word (`Letters.earlyWord`): a three-tile word whose letters are all known, with a picture, asked as a first-sound round with three tiles, the answer, family words' first letters where known, and other known consonants, never two sound-alikes. It counts as reading the word; stage 0 still ends only when every letter is known. The round is noted as `early_word:<w>`.

## Puzzle kinds

`puzzle/Puzzle.java` is a target, its family, the shelf, the gap slot and the kind: `FIRST` (gap 0), `LAST` (the last tile) or `MIDDLE` (tile 1 of a three-tile word, a vowel). `frameOf` blanks the gap to key a family; first and last families are one stage's words, middle families every stage up to the child's. `pick` takes the kinds `Room.kinds` allows (first always, last once three in five of the stage are read, middle from stage 2, each behind its `puzzles` setting), prefers kinds and frames with something unread, and if none of them can reach an unread word uses whichever kind can (web is only in `we_`, gem only in `g_m`). `forTarget` tries first, last, middle. The room puts the gap at `puzzle.gap()`; everything that depends on where the gap is (the row, `inGap`, row sounds, breaking, aiming, swapping, the blend) goes by it.

`keyword: true` is "also a keyword"; `puzzle: false` is keyword-only, and `Words.all()` is only the puzzle words.

## Two-letter tiles and whole words

`Letter` has the two-letter tiles after `BLANK` (sh ch th ck qu ll ss ff zz ee ea oa ai oo ie gg, then ar or ur ir er ow ou ay igh oi oy ng nk; `Letter.isVowel` counts the vowel-sound ones, which are red and cut from the word; igh is drawn by `triple_texture`, each letter only as wide as it is), each a `letter` block state with its own texture (`generate_textures.py` draws both glyphs at scale 2) and model (`generate_models.py`). `Letter.of` reads them; `isSingle`, `isDigraph`, `isVowel` tell them apart. A word's tiles can be graphemes, so `Word.letters()` covers them; the hybrid blend's cut clip is for vowel tiles only (qu is not one). A two-letter tile is learned by reading words with it first try (`Prizes.solved` counts each), against `letter_known_after`.

`Puzzle.Kind.WHOLE` makes every slot a gap (`Puzzle.gaps()`); its frames are single words with no tile twice, its shelf the word's tiles and up to two decoys from what the child knows (`RoundLifecycle.known`), at most `MAX_WHOLE_TILES`, and its family every word of that length so a real word built instead is that word. It is open from stage 6 (`Room.WHOLE_FROM`) and is the fallback for any unread word no other kind reaches. The room keeps `gapMarkers` (each gap and its underscore); `aimedGap` says which gap a tile is placed into; `built()` is null while any is empty, which `press` answers with "hmm"; a wrong or nonsense build sends every gap's tile home.

## Phrase variants

`Sounds.variantsOf` groups `phrase/<name>_v<n>` recordings under their line; `Sounds.variant` deals one per player from a shuffled bag, never the one they heard last. `Narrator` picks the variant as a step starts, so length and caption are the variant's own, logs `clip:<line>` plus `variant:<chosen>`, and `Narration.sayExactly` skips it (the Phrases screen).

## Visible prizes

A payout (`Prizes.pay`/`payOwed`) queues its items and experience in the room (`Rooms.prizeAdded`); the "You earned a prize!" step (`PrizeShowcase.prizeLine`, in the prompt and the right flow) calls `deliverPrizes`: the chest pops up if needed, then each item is an item display flown from the button to the chest (`PRIZE_FLIGHT` ticks, `PRIZE_GAP` apart), the lid opened with block events, experience a stream of dust. These run on `Later` guarded only by the room still being open (not by the round), so a new round mid-flight doesn't strand one. The haul over the chest is rebuilt as things land; `beginLeaving` sends it to the child; `close` removes it.

## Leaving

`Travel.leave` says the prize line and goes home on a `Later` timer, not as a step of that line's narration: any narration started meanwhile would otherwise stop the way home (the live bug where a child with prizes could never leave). `Room.beginLeaving` then stops the room starting anything new, and records when; `Rooms.tick` sends home anyone still leaving after five seconds, and `leave` while already leaving tries again rather than doing nothing. `goHome` and `handBack` skip a dead or dying player: the respawn backstop does it. A right answer's narration cut short after the word has happened still moves on to the next round, from its `onStop`. The disconnect handler runs on the server thread, cancels the player's `Later` jobs, and closes the room only if it is still the one they had (`Rooms.forget(player, had)`), so a quick relog's fresh room is never closed by the old disconnect.

## Mastery, gates and daily schedules

A word's clean completions are its `Memory` item's first tries (`Progress.clean`); `Progress.masteredAt()` is `mastery_clean` (default 3; `PrizeConfig.migrate` turns an old `letter_known_after` into it, its old default 2 becoming 3, and writes the file back). `Stages.complete` is every word of the stage mastered, so `Stages.current` is the gate; letters use `letterHits` against the same count. `Puzzle.pick` is given the mastered ids as done, the clean counts, and the last target to avoid (at the kind, family and word level). `AnswerCommit.lastOfStage` and `masters` look at this completion; the word's memory is recorded before `Prizes.solved`, so `stage_complete` sees the stage mastered. A mastered word missed drops a box, not to box 1. `Progress.gate` (once, for a save whose memory is not `gated`) sets the stage floor to the stage reached by words read. Test hooks: `Progress.masterForTests`, `setCleanForTests`, `setForTests`, `PrizeConfig.useMastery`.

`classroom/Schedules.java` reads and writes `config/learning-blocks/schedules.json`; `Progress.today()`/`date()` use its time zone (`useInstant` and `useClock` stand in for tests). `AnswerCommit.right` counts each solved round for today (`Progress.doneToday`). `Travel.loggedIn` ends with `Schedules.enforce`, which uses `Travel.send` and sets `Room.learningTime` for "Learning time first!" (`reading_time` for a child with only Reading on); the last lesson's line is `done_for_today` when `Schedules.metToday`. `Travel.kept` lets an operator out unless scheduled today. `Schedules.tick` notices a day turning while online, and acts only with `enforce_on_rollover`.

## Read it, memory and progress

A read-it round (`RoundLifecycle.pickReadIt`, only words with `Word.clearPicture()` (`"picture": "clear"`), and only clear choices: the families' first, then other clear words of the stage sharing the first or last tile, from stage 2, one in `read_it_every`, `PrizeConfig.readItOn()`) takes a read word with at least one family word pictured differently: the puzzle is the target with those words as its family and no shelf; the row shows every tile and has no gap; `placeChoices` puts each picture on a slab with an `Interaction` box, and `Rooms.clickEntity` passes a click or punch to `AnswerNarration.pick`. The prompt is `phrase/what_does_it_say` (and its variants), never the word; the button asks again. Right: counted at the pick, then `soundOut` and `tellRight`, as a built word. Wrong: `phrase/oops_thats` and the picked word, a wiggle, asked again. Logged `read_it:<w>` and `picked:<w>`.

`reward/Memory.java`, saved in `Progress` (`memory`): per `word:<id>` and `tile:<grapheme>` item, attempts, first tries, misses, the last five things built instead, and a Leitner box (a miss to 1, a first try up one, 5 at most) with the round it was last seen; due after 2, 5, 12, 30 or 80 rounds by box. `Progress.wordRight`/`wordMissed`/`letterAnswered` record it (the gap tiles, and a mix-up pair for each tile that differs), `roundBegan` counts rounds, by day too, `timeSpent` is added when a room closes, and `lessonNote` keeps the lessons history. `RoundLifecycle.dueWord` and `Letters.pickTarget` take a due item `review_share` percent of the time. `PrizeConfig.extrasOffForTests` (set by `TestDefaults`) turns read-it rounds and review off for the tests that expect the round they asked for; `useReadIt` turns them on.

`review/ProgressView.java` is the grown-ups' screen and the JSON export. `Review` stars due items (`Review.starredShown` for tests). `Outcome.Hut` takes a `block` (a wool tent, a brick house).

## Magic e and mod words

A magic-e word's tiles are letters, its vowel's `sounds` entry the long sound (`a_long`) and its final e `silent`. `AnswerNarration.magicVowel` finds that shape; at the silent e's step the e and its vowel light together, an end-rod trail runs from the e to the vowel with a chime (`magic_e:<index>` in the log), and the caption shows every long vowel as its capital. `phrase/magic_e_<v>` ("The e makes the a say its name!") follows the word once a visit per vowel, but only once it is recorded (`Sounds.isRecorded`).

A word file's `requires` (mod ids, checked with `FabricLoader.isModLoaded`) leaves the word out at load, logged. An `Outcome.Prefer` runs the first of its `options` that is `usable()`; `Word.picture` pictures that one. Mod things are named by id like any other, so a missing mod is just an unusable option.

## Hardening

Nothing a tick does can take the server down or leave a child stuck. `Safely.run` wraps each `Later` job, each room's tick (`Rooms.tick`: a room that throws is closed and its child sent home), `Classroom.tick` per player, and each narration's advance, `when`, action, `onStop` and sound; a failure is logged and that job, room or narration dropped. An answer is counted when the button is pressed (`AnswerCommit`), each part in its own `Safely.run`: progress and prizes, then the lesson; the narration after is only presentation, and an outcome that throws costs nothing but its showing. A loot table that throws on a roll is caught in `Prize.resolve`. A room with no puzzle for ten seconds while lessons are left lets them go (`Room.strandedLessons`), and `/learn send` refuses lessons where no puzzle could be made (`Rooms.puzzleAvailable`).

Saved items are read leniently (`classroom/LenientItems.java`): the stash, the visit's prizes and a child's owed payouts decode item by item, and one this server can't make becomes a paper "Missing item: <id>" holding the saved data, which is written back exactly as it was, so the item returns if its mod does. A whole `Progress` that can't be read is kept as it was saved (`Progress.SAVED`, `unreadable()`) and logged loudly, never replaced with a fresh one. `Travel.enter` is all or nothing: the visit (with the cursor item, the 2x2 crafting grid, and health, food, air and fire) is written first, and if building, teleporting or starting fails, everything is handed back. Plots are allocated from one overworld map (`Plots.ASSIGNED`), and the counter never goes below the highest plot handed out. Words are de-duplicated by their tiles when loaded (the first wins), and answers are compared by tiles, not by which file a word came from. `Hardening` tests the backstops, a throwing outcome, stranded lessons, the unknown item, an unreadable progress, and a disconnect while leaving.

## Bands

`Stages.bands()` splits each stage into `Stages.Band`s (cached per word list and mastery count): words sorted by `Stages.order` (their tiles' letter groups, latest first, then the text); the first two stages from 1 split by `hardest` group into group 1, group 2 and the rest (`byGroup`, a band under `SMALLEST_BAND` joining the one before, or after if first); any other whose words times `mastery_clean` pass `LONG_STAGE` (45) split into halves. A band's `code()` is stage * 100 + index; its `label()` is "1b", or "3" for a stage in one band. `Stages.currentBand` is the first band at or past `max(stage_floor * 100, band_floor)` with a word unmastered; `Stages.current` is its stage. `RoundLifecycle.newRound` passes `Puzzle.pick` a `targetable` predicate (the band's words): frames are still built from the whole stage, only families with a targetable word are kept, and the target is always targetable. A change of band is a fresh start (`Room.band`), `AnswerCommit.lastOfStage` is the band's last word, and `Prizes.solved` pays `stage_complete` per band (`stages_paid` keeps band codes; a plain stage number there, from before bands, counts as all its bands paid). `/learn stage` parses a label (`Stages.parse`) and `Progress.setBand` sets `band_floor`; `setStage` clears it.

## Tricky words, capitals, plurals and phrases

Tricky words (`"tricky": true`, `Words.tricky()`) and plurals (`"plural": true`, `Words.plurals()`) are loaded apart from `Words.all()`, so no stage waits on them. `Words.shown` is a word's `shown` tiles (I is `cap_i`). A tricky round is a read-it round with `Room.tricky`: `RoundLifecycle.trickyPuzzle` makes the target and two other tricky words (same length first) its cards, `card` draws each as a text display on a tile-coloured background, `ask` says `word/<w>` with a `starred` caption (and `phrase/find_this_word` if recorded), `AnswerNarration.pickTricky` never sounds out; `Interaction.rowSound` has its letters say the whole word. They come one round in `TRICKY_EVERY` (6) from stage 2 (`pickTricky`: open at the stage, unmastered, fewest clean first; then due ones). Plurals come one in `PLURAL_EVERY` (8) at stage 6 and past, for a read base word (`baseOf`): `pluralPuzzle` is `Puzzle.Kind.PLURAL`, gaps 0 and the last tile, shelf the onsets of the plurals sharing its rime and `s`; the family is those plurals, so building one runs its outcome. Phrases (`puzzle/Phrases.java`) come one in `PHRASE_EVERY` (7) at stage 6 and past, from a read adjective in `Phrases.ADJECTIVES` and a read creature word with a real first-sound family; the adjective's tiles go a row above the word (`placeAdjective`, `Room.adjectiveRow`), the noun is an ordinary first-sound round, `AnswerNarration.blend` says the adjective first and both words after, and a built creature word runs `AdjectivePhrases.run` (big: `Attributes.SCALE` 1.8; six: six spawns; red: a sheep dyed, red dust; wet: dripping water; fun: hops and fireworks) instead of its outcome. Extras stay off in tests unless forced (`PrizeConfig.extrasOn`); `Rooms.startTricky`, `startPlural` and `startPhrase` force them.

Capitals are `Letter.CAP_A`..`CAP_Z` (`isCapital`, `upper`, `lower`, `shown`), tile textures `letter_cap_<x>` from `generate_textures.py`. `Letters.pickCase` picks a letter whose sound is mastered and pair isn't; `RoundLifecycle` makes one round in three at stage 0 a case round once one is due (every round, once no sounds are left), and `CASE_REVIEW` percent elsewhere; `casePuzzle` is the shown tile and a gap, with `Letters.caseDistractors` (known letters, never a `MIRRORED` partner). `AnswerNarration.pressCase` says the name (`LetterBlock.nameOf`), runs `caseLink`, and counts via `Progress.caseAnswered` (`letterHits` under `case:<x>`, memory item `case:<x>`). `Letters.caseKnown` gates a group and `Letters.complete`; `Memory.casesChecked`/`casesWaived` are set once, waiving pairs for a reader who knew every sound before capitals existed.

## The portal, days and names

`puzzle/Portal.java` is the way home: a frame (`RoomLayout.portalFrame`, polished blackstone bricks dark, crying obsidian lit) round a two-by-three opening (`portalLower`, `opening()`), barrier blocks across it while `Travel.kept`, a purple stained-glass `BlockDisplay` and `PORTAL`/`WITCH` particles while open. `Portal.tick` (from `Room.tick`) sends a player whose bounding box overlaps the opening, facing into it with the forward key held (`getLastClientInput`; so a push from fan, a spin, or backing up to see the board never does), home through `Travel.leave`, debounced, and notes `portal:enter`; locked, a player pressed against it notes `portal:bump:<n>` and hears `more_to_go_<n>` at most every 80 ticks. A click on the frame works too. The last lesson's line is `Portal.openLine`: `phrase/portal_open`, or `done_for_today` when the day's schedule is met. The action menu suggests **Go home** (`learn leave`), which says `more_to_go_<n>` while kept. Entity clicks go through `Rooms.useEntity` in an early `UseEntityCallback` phase (`classroom_first`): the room's own clicks, then anything in the classroom but a vehicle is consumed (both hands), so other mods' listeners and villager trades never see it.

`Memory.today`/`usedToday` keep the day's lessons (`<word id>|<kind>`, kinds `first`, `last`, `middle`, `whole`, `plural`, `read_it`, `tricky`, `scene`, `phrase`, `case`, `letter`), recorded as each round starts (`Progress.useToday`), emptied when the day (`Progress.today`) changes. `RoundLifecycle.freshPick` is the usual pick with words used today excluded, then the fill order (notes `fill:kind:`, `fill:read_it:`, `fill:scene:`, `fill:review:`, `fill:case:`, `fill:phrase:`, `fill:repeat`); the read-it, scene, review and tricky pickers skip words used today too. `Memory.counted` keeps the day each item last counted clean: `Memory.right` and `Progress.hit` (letters, two-letter tiles, pairs, under `hit:<key>`) count one a day, and `AnswerCommit.masters`/`lastOfStage` and the letters level's mastered checks ask `cleanCountsToday`/`hitCountsToday`. Test switches: `Memory.spreadOffForTests` and `Progress.repeatsForTests`, both on in `TestDefaults`.

`LearnCommand.reader` finds a daily schedule's reader online, in the schedules, by UUID (named from `services().nameToIdCache()`), or by name from the same cache, only if already in it (`mixin/CachedNamesAccessor`; the cache's own lookup would invent an offline id); `playerOrOffline` gives `send`, `lessons`, `release` and `progress` a message naming an offline player instead of "no player was found". `Travel.loggedIn` calls `Schedules.refreshName`.

## Reading together

A `Room` has `members` (owner first, at most `MOST_READERS`); `Rooms.rooms` maps every member to it. `Rooms.join` moves a reader in (closing their own room); `Rooms.close` takes one reader out (`Room.removeMember`: their chest goes, the room passes on if it was theirs, and their round gives way to the next reader's) and closes the room only with the last. `Rooms.open` on a plot whose room still has readers joins it. `Travel.readWith` (from outside by `enter`, or across inside), `Travel.readAlone` (unpair). `Rooms.tick` runs each member's `Room.tickMember` (their portal, their lessons) and the room's `tick` once, for `turnPlayer()`; the leave watchdog is per member (`leaving(player)`, `leavingFor(player)`; `leaving` alone is the whole room closing).

`Narrator.hearAlong` (set by `Rooms`) mirrors each clip and caption to the others in the room; what a step does, it does once, for the narration's own player, whose log it is. `RoundLifecycle.newRound` takes the turn (`Room.takeTurn`, the next reader on an ordinary new round) and picks from that reader's `Progress`; each reader's last stage and band are kept (`lastStage`) so the other's is no fresh start. Gaps belong to a reader (`gapOwners`, underscores `Letter.BLANK_BLUE/ORANGE/GREEN`); `Room.mayPlace`/`mayPress` refuse others (`notYourTurn`), in `Rooms.useBlock`, `mayBreak`, the button and read-it picks. Team-ups (`Kind.TEAM`, gaps first and last): `teamPuzzle` from the lower reader's band with both a first-sound and a last-sound family; `AnswerNarration` credits each reader (`commit.right` each, `wordRight` with their own slots, `prizeLineFor` the other's chest) and charges a miss to `gapPlacers`. `PrizeConfig.teamUpEvery` (`team_up`, `team_up_every`; `teamUpForTests`). Each reader has a `PrizeShowcase` at `RoomLayout.prizeMarker(place)`. `Portal` walls the opening only while it is shut for everyone, turns back a kept reader from an open one, and sends each reader their own frame (block packets two ticks after the real ones). Markers: a coloured `▼` text display kept over the turn reader (both in a team-up). `Schedules.together` (`together_with` in schedules.json); `Schedules.enforce` moves a scheduled reader into their partner's room.

## Subjects

`subject/Subject.java` is a subject: `id`, `label`, `colour` (the board frame), `hello` (the switch line), `canAsk`, `round(player, kind, target, random)` (a `SubjectRound`, or null; Reading's is always null, since its rounds are the room's own), `kinds`/`targets` (the sampler), `items`, `mastered(progress, item)`, `summary(progress)` (the parent view). `Subjects.ALL` is Reading, Numbers, Logic; `Subjects.on(player, subject)` (the child's own `Progress.subjectOn`, else `PrizeConfig.subjectOn`; `onlyForTests` overrides both, and `TestDefaults` sets reading only); `Subjects.pick(player, last, run, random)` applies the daily split (`Schedules.perSubjectToday`, `stillNeeded`) then the mix (`PrizeConfig.subjectMix`, `subjectBlock`, `subjectWeight`); `Subjects.mastered(progress, "numbers:numeral:5")` for any subject's item.

Item ids are `<subject>:<kind>:<item>`. Numbers and Logic keep theirs in the child's one `Memory` under those keys (`Progress.itemClean`, `itemMastered`, `itemRight`, `itemMissed`, `useItemToday`, `itemUsedToday`, `setItemCleanForTests`); Reading keeps the keys it always had (words by id, letters, sentences) in its own fields of `Progress`, and `Reading.mastered` answers `reading:word:<word>` and `reading:sentence:<goal>` from them. `Progress.SubjectState` (the codec's optional `subjects` field beside the old ones, which stay under 16 to a group in `FIELDS`) holds each child's own on/off and today's count per subject (`solvedToday(player, subject)`, `doneToday(subject)`).

`RoundLifecycle.newRound` picks the subject after the turn (anything of Reading's asked for by a test hook or the sampler is Reading; `Room.forcedSubject` is another's), and a non-Reading subject's `round` becomes `Room.subjectRound`, with a placeholder `puzzle` so everything that asks whether there is a round is told yes (as for Bob). `noteSubject` keeps each reader's last subject and run (`lastSubject`, `subjectRun`), queues the hello (`pendingHello`, said first in `prompt`), and paints the frame (`Room.frame`). `puzzle/SubjectRound.java`: choices on the floor at `shelfSpot` with an `Interaction` box each (`Rooms.clickEntity`), the right one through `AnswerCommit.right` (the subject's `currentSubject` counted for the day), `Prizes.itemSolved`, `Earned.checkItem` and the level's `Prizes.levelComplete` (the `stage_complete` event, once per `level:<subject>:<n>`); a wrong one through `AnswerCommit.wrong`, said, and asked again. The button asks the round (`SubjectRound.press`; by default, asks again). A kind can override where its choices stand and what stands there (`spotFor`, `stand`, `hitWidth`), hold a pick without a verdict (`judge` HOLD, `hold`: a tile into a gap, the next number into a row) and give it from the button (`press`, `conclude`), act before the verdict (`act`: Bob does what the card says), and tell right and wrong its own way (`tellRight`, `tellWrong`).  `Earned.linkItems(toy, items)` links a toy to any subject's items (a toy with words and items needs both). `numbers/NumberBlock.java` and `generate_numbers.py` are the number tiles.

## Plushies, toys, props and picture cards

`generate_plushies.py` draws the plushies: each is a few boxes in a block model over a 64x64 sheet (felt swatches on top, the face below, and an optional pattern, e.g. a snail's spiral or a ladybug's spots), with optional element rotations (the moth's folded wings). It writes the models, the textures, the `plush` blockstate (by `kind` and `facing`), an item definition for each `plush_<name>`, the loot table (one entry a kind, each conditioned on it) and the names. `plush/`: `Plush` (the kinds; the names must match the script), `PlushBlock` (one block, `kind` and `facing`; right-click squeaks, `lastSqueezed` for tests; pick-block gives the right one), `PlushItem` (one item each, putting the block down as its kind), `Plushies` (registration, `stack`, `item`). `generate_toys.py` draws the toys the same way (felt swatches in the top-left quarter, up to three painted pictures in the others, a box's side a swatch or `@picture`), reusing the plushies' face drawing and the letter tiles' wood (`generate_textures.tile`, `stamp`) for the ABC block. It writes the `toy` blockstate, the models, textures, an item definition for each `toy_<name>` (the cap and the wig switch to their worn model on the head via a `display_context` select), the loot table and the names. Loot tables are in 26's shape: a pool's `condition` (one object, `minecraft:match_block` with `blocks` and `state`, or `minecraft:survives_explosion`). The older `conditions` list and `block_state_property` are not read and fail silently, so every pool pays out; the plushie and toy tables, one pool a kind, would then drop every kind at once, which shipped once. `PlushiesAndThings` and `ToyPlay` break every plushie, toy and prop (at rest and mid-play, and the crib with the doll, the car with the owl) and check the drops are exactly the thing itself (`Drops.expect`). `toy/`: `Toy` (the kinds and each one's `Sound`; the names must match the script), `ToyBlock` (as `PlushBlock`; a right-click plays its sound and says `word/<toy>` when recorded), `ToyItem`, `Toys` (registration; the cap and the wig are equippable on the head). `generate_emotes.py` draws the feelings' bubbles and the waving hand (`textures/item/emote/`, `items/emote/`). `generate_things.py` draws the worn cap and wig (worn like a carved pumpkin), the props as models over vanilla textures (two of their own: the jar's glass, `prop_jar`, and the corn's kernels, `prop_corn`), and the picture cards (`textures/card/`). `props/Props.java` registers the props (the names must match the script); `PropBlock` faces its placer and takes its model's shape turned to match.

`generate_textures.py` draws the letter tiles as wooden toy blocks, 64 pixels a face: `tile()` is the grained wood with its rolled edge, raised border and recessed panel (lit: the same washed yellow), and `stamp()` paints a glyph with a thin shadow.

`Prize.Plushie` (`"plush"`): `Progress.choosePlushie` (random_new: one not owned, else any), `ownPlushie`, `plushies` (in `Memory.plushies`). `Prize.Toy` (`"toy"`): `chooseToy`, `ownToy`, `toys`, kept in the same map as `toy:<name>`. `Prize.Toybox` (`"toybox": "random_new"`): `toyboxPicksToy` weighs the two shelves by how many each is missing, so every missing one is equally likely. `PrizeShowcase.prizeLine` says `phrase/new_plushie` or `phrase/new_toy` when the news includes one just got for the first time. The editor's `Row.Toybox` shows a plush, toy or toybox prize; a plushie's arrows step through random_new and every plushie, a toy's through random_new and every toy; `plushadd`, `toyadd`, `plushrm`. `Review.Tab.TOYBOX` draws two shelves (`toyboxShown`, `toyboxCount` for tests); with six tabs or more, long tab labels go short.

`PictureCards` reads `textures/card/<name>.png` into a Pandorical `Picture` (a palette of the image's colours, transparent cells clear, a cream back) and shows it anchored to the board picture's click box (`BoardPicture.showCard`), for a word with `"picture_card"` (`Words.pictureCard`). Limits: Pandorical clients only (vanilla clients see nothing), up to 512 cells a side and 256 colours, anchored to an entity and gone with it, not persisted, and the API is marked not yet stable.

## Sentences with Bob

`bob/`: `Noun` (every thing Bob knows: its kind, creature, plushie, container, surface, wearable or lid; what stands for it, an entity type, a plushie, a toy as `toy:<name>`, a block or an item; and its height), `Instruction` (put [the|a] [big] X in|on|under [the|a] [big] Y, parsed exactly), `BobScene` (where everything is, changed one instruction at a time by the literal rules: in a creature is on its head, a creature on a creature rides it, under something with no room under it swaps them, nothing goes in a container with its lid on), `Goal` (one or two sentences, their start and end scenes, `madeBy`), `Goals` (the list in order, `open` by shape, `pick`, `decoys`, and `wrong` for what's-wrong rounds).

`puzzle/BobRound` is a round with Bob: the cards (text displays with click boxes), the rows of slots on the board, Bob (a villager, no AI), the framed goal pictures (`BobStage` at 0.6, on a mat of block displays) and Bob's stage (`BobStage` at full size). `BobStage` shows a `BobScene`: creatures as creatures (no AI, no gravity, invulnerable, a creature that rides another really riding it), everything else a block display of its block (an item display for the hat), and every change glides. Lines not yet recorded (`phrase/tell_bob`, `phrase/pick_for_bob`, `phrase/silly_sentences`) carry their caption in the step (`CaptionLine.plain`).

A word to fix is an ordinary word round with `Room.fixLetter`: `RoundLifecycle` picks a letter that spells another family word in the gap (`fixLetterFor`), puts it in the gap and empties its home, and asks with `phrase/whats_wrong`; `Rooms.startFix` for tests and the sampler.

## Big words

`Words.chunks` (a big word's `"chunks"`, read beside the codec and checked to add up to its tiles), `chunkRanges`, `compound`. `Puzzle.Kind.CHUNK`: `gap` is the first tile of the chunk to build, `gaps()` that chunk's tiles; `buildableChunks` (no tile twice in the chunk), `Puzzle.chunk` (the chunk's tiles and up to two decoys), frames one word each like WHOLE; WHOLE is only for words of six tiles or fewer. `RoundLifecycle` lays a chunked word out with a column between its chunks (`RoomLayout.rowSpot` moves a long row left, clear of the button; `pictureAbove` puts the picture over a row that starts near the wall). `AnswerNarration.soundOut` sounds out each chunk and says it (`word/<chunk>`, label `chunk:<text>`), then, right, `join` slides the later chunks along into the column (`joined`) before the whole word. `Stages.order` puts a stage's compounds before its two-syllable words. ## Relations, play and toys earned

`relate/`: `Thing` (a thing's data: what it is, how it is shown and held, height, tags, wearable, lid, and `holds`: in, on, under, ride, each with what it accepts and the pose there) and `Relations` (loads `learning_relations/*.json`, written by `generate_relations.py`; `resolve` is Bob's literal "put x in/on/under y", `fit` the world's gentler "can this go there", `holdFor` the pose; `forItem`, `forBlock`). `bob/Noun` is a view of a `Thing`, `BobScene.apply` calls `resolve`, `BobStage` places by each hold's pose, and `Goals.all()` is the written goals plus one per small thing and thing that `fit`s it (made again on every reload). `BobRound.Mode.PREP` is the little-words round: `makePrep` finds a readable pair two prepositions put in different places (`prepDiffers`), shows both as pictures, and a pick is right or "try again".

`play/`: `Play` hides a toy or plushie block (`HIDDEN`, an empty model) while a block display of it (or, for a toy drawn in parts, an item display of its body and one of each part, `toy_part/<toy>_<piece>` by the item model component; `generate_toys.py` writes a box's `"part"` as models of its own) plays its `Anim` (key poses in the toy's own frame, glided between, with sounds and puffs; `Anims` has one per toy, the plushie `SQUISH` and the tub's `FLOAT`), carrying whatever is in it; the block shows again at the end, and a block tick scheduled for just after (`recover`) puts it right if the play never finished (a chunk unloaded, a restart). Things put in or on a block (`put`, `takeOut`, `removed`, `showIn`) are item displays at its foot, tagged with how they went, saved with the chunk like any entity. Toys, plushies and props are `instabreak`, and Pandorical's copy has strength 0.

`reward/Earned`: each plushie and toy's words (`Words.earns`: the plushie or toy a word's icon or outcome names, or its file's `"earns"`), `check` after every solved word and on the way in, and `Prizes.toyMastered` paying the toy (unless already owned) and the `toy_mastered` event's prizes. `Review` shows a not-yet-owned toy's word and pips. A scene's `place` can `tuck:<item>` a toy into the placed block.

## Sky, weather, feelings and gestures

`classroom/Sky`: the classroom's dimension type has no fixed time; it keeps time by a world clock of its own (`world_clock/classroom.json`), its sky drawn by two timelines on that clock (`timeline/day.json` and `moon.json`, the overworld's visual tracks only, written beside it), and the server pauses that clock at noon. `TimePacketMixin` rewrites every `ClientboundSetTimePacket` sent to a player in the classroom so the classroom clock is theirs (`Sky.rewrite`): frozen at their time, or for a glide (`Sky.glide`) where it starts and its rate, so their game draws the sunrise itself and is told once more when it stops; nobody else's packet is touched. Weather is the game's own rain, sent to the one player (`ClientboundGameEventPacket` START_RAINING, RAIN_LEVEL_CHANGE, THUNDER_LEVEL_CHANGE, eased a tenth every four ticks; STOP_RAINING then the levels at nought, since the game takes STOP_RAINING alone to mean full rain about to fade). `LevelMixin` keeps the classroom's server level dry, so nothing real ever falls or strikes; each room is painted with the classroom biome (`worldgen/biome/classroom.json`, which rains) and repainted cold (`classroom_snowy`) for snow; the room has no lid, so rain falls in, and `Classroom.care` puts anyone up over the walls back on the floor. A storm's flash is a lightning bolt only that player is told about, far off, visual only, removed again, with a thunder sound. `Sky.dark` is a Pandorical shade over the screen. A cloud is five block displays drifting once across the room. `Sky.reset` (the next round, `RoundLifecycle.clearRound`) glides back to noon and clears the weather and the dark; `Sky.forget` (leaving the classroom, logging out) forgets it all, and the world's own time and weather are sent on the way out as ever. The overworld's own START/STOP_RAINING, broadcast to everyone, is answered with the child's own weather (`Sky.overworldTurned`).

`feel/Feelings`: a feeling is an item display of paper with its item model swapped for `emote/<face>` (`generate_emotes.py`: a 32x32 bubble with a pixel face; and the waving hand), billboarded, riding whoever feels it, popping up and shrinking away. Tracked, and one met in the world untracked (saved with a chunk) is discarded as it loads; a bubble is tracked before it is added for that reason. `feel/Gestures`: a gesture is worked out tick by tick for an entity with no mind of its own (`Pose`: offsets, a body turn, a head turn and a nod), then it is put back exactly; a wave holds up the hand picture, hiding brings a block display bush, both tracked and gone with it. `Outcome.Character` brings a character through `Stage.dispenseCharacter` (no AI, no gravity, a scripted hop to stand in front of the child); `Scene.Feel`, `Gesture`, `Sky` and `Weather` are scene steps; `SceneRun` waves a still villager hello, and at the end shows everyone glad and has the one it was about nod. `BobRound` waves Bob in, nods him at `bob_okay`, shakes his head at a miss and makes him jump, glad, at a right sentence. `Phrases` has sad, glad and mad. `PlushBlock` shows a love or glad face over a squeezed plushie. `particle-emote` has no API for faces over an entity (its emotes are players' own particle bursts), so none of this uses it.

`bob/Goals.pick` keeps goals with only props in them (`propsOnly`: a made goal with no plushie, toy or creature) to `PrizeConfig.bobPropShare` (`bob_prop_share`, 20) and never after another, and otherwise prefers ones with a plushie or toy.

## Room's parts

`Room` holds a round's state and the timing (`tick`, `later`, `close`); the rest are its own classes in `puzzle/`, each given the room and working on its state: `RoomLayout` (where everything is, and building the walls, board, button and portal), `RoundLifecycle` (picking a round, a letter, a scene or a letters-level word, laying it out, asking it, clearing it), `Interaction` (a right-click, tiles into and out of gaps, `keepSolvable`), `AnswerCommit` and `AnswerNarration` (the button: counting the answer, then telling it), `Dispenser` (everything words do, and what they left: creatures, props, placed blocks), `PrizeShowcase` (the chest, prize flights and the haul), `Portal` (the way home and its count) and `BoardPicture` (the picture and its click box). `Outcome` and `SceneRun` see only `RoomEffects`, the dispenser's side.

## Situations

The scene engine (`Scene`, `SceneRun`) takes up to three characters (slots on the spot, in front and behind), acts `bounce`, `stuck` and `hungry` besides the rest, blocks at offsets that `become` something on the solve (applied by `swap` in `finish`, or at once by a `soak`), `wrap`, `ring` (joined up with `Block.updateFromNeighbourShapes`) and `prop` in the setup, and `pose`, `visit`, `tune`, `effect`, `hut` and `give` to `all` (with `snip`, `pull`, `soak`) in the solve. Every square it uses is in `occupied`, which `Dispenser.free` and `Dispenser.hutMay` keep clear; the scene's own hut may build over them.

A word's optional `scene` (`puzzle/Scene.java`) is its setup and solve steps. `RoundLifecycle.newRound` asks `pickScene` for one when `puzzles.scenes` is on and `scene_every - 1` rounds have passed since the last this visit (a counter, not a roll, so tests can tell): a random read word with a usable scene, not the last one if there's another, never on a new stage's first round. A scene round has no picture; `SceneRun` (per round) spawns the character at `Room.sceneSpot()` with no AI, tagged and invulnerable like any word's creature, keeps its ambients going from `Room.tick`, and reserves its squares from `Dispenser.free`. `prompt()`/`ask()` say `scene/<w>` and `phrase/what_can_help` instead of `make_the_word`; `outcome()` runs the solve instead of the word's outcome for the target; the right flow then says `that_helped`. `SceneRun.end` (from `clearRound` and `close`, which logout reaches) discards everything it made and hides the dim overlay, a full-screen Pandorical HUD panel (`learning-blocks-justfatlard:dim`). `CaptionHud` takes its overlay down before putting a line up, so the caption is always drawn over the dim. `PrizeConfig.useScenes` is a test hook; StageWalk turns scenes off.

## The prize editor

`editor/PrizeEditor.java` is PvP Dimensions' preset editor made for one file: tabs, a row per setting with its control, 316 wide so it fits 320x240. The file is the model. `PrizeFile` reads it as a JSON tree (comments allowed), a press changes the tree at a path, writes it back with the mod's own comments (`PrizeFile.text`), and `PrizeConfig.load` reads the config back from the file exactly as `/learn reload` does. Component ids carry the setting's path (`next:events.streak.length`), not a row number, so a press after a hand edit still means the setting it says. `PrizeEditor.press` is the same path for tests.

`editor/PrizeSessions.java` is `ItemSessions`: the operator's pack is put aside in a persistent, copied-on-death attachment, the list's items are laid out, and whatever they hold at `/learn prizes done` becomes the list's item entries, written with the item codec so components survive. Editing and the classroom refuse each other. Entries this server can't make (a missing mod's items) are never laid out and are kept. `editor/LootPicker.java` is `BlockPicker` as a list of loot table ids. `editor/ServerSettings.java` puts the four simple settings on Pandorical's server settings, backed by the same file change.

`narration/CaptionSettings.java` is each player's captions on/off, size and position through `SettingsApi.group`; `CaptionHud` reads them on every line.

## Getting in and out

One way in (`Travel.enter`) and one way out (`Travel.leave`); the command and the portal both use them. The `Visit` attachment on the player - persistent, copied on death - holds home, the pack slot by slot, experience, game mode and effects, and is written before anything is taken. The backstops:

- **Login**: logged out inside with a visit, they carry on in a fresh room; with a visit but somewhere else, they get their things back where they stand; inside with no visit, they go to spawn.
- **Respawn**: a death inside ends the visit at the respawn.
- **`AFTER_PLAYER_CHANGE_LEVEL`**: moved out by something else, they get their things back; moved in without a visit, they are sent to spawn. Both are deferred a tick with `server.execute`, never done inside the event, which fires from the middle of a teleport and can recurse without end if the player is turned round from there.
- **`/tp`**: refused across the border either way, by `TeleportCommandMixin`.
- **Forced**: `Travel.forceHome` (`/learn home`, and the stuck detector) is `goHome` with the visit's lessons cleared and the prize line skipped. `Travel.leave` records each try (`triedToLeave`); `Travel.checkStuck`, from `Classroom.care` each tick, sends home a child not kept with three tries in thirty seconds and none for ten, logging `STUCK:` with `Rooms.stateForLog` (round, busy, leaving and for how long, portal, readers, lessons, prizes, narration, where). `Room.strandedLessons` logs the same way. `Travel.wedgedForTests` makes every ordinary way home do nothing. The portal also takes a child wholly inside its opening for `Portal.SETTLED_IN` ticks who walked there themselves (any movement key held), any way round.
